# REST API conventions

The contract is OpenAPI 3.1, generated by huma from Go types: `GET /api/v1/openapi.json`, documentation at `/api/v1/docs`. The SPA's TS client is generated from this file; there are no hand-written fetch calls in the SPA.

## General rules

- Base path `/api/v1`. JSON, UTF-8, field names in `camelCase`.
- Errors — RFC 9457 `application/problem+json`:
  ```json
  { "type": "about:blank", "title": "Not Found", "status": 404,
    "detail": "entry does not exist", "ldapCode": 32, "ldapMatchedDN": "dc=example,dc=com" }
  ```
- LDAP → HTTP mapping:

  | LDAP result | HTTP |
  |---|---|
  | 32 noSuchObject | 404 |
  | 68 entryAlreadyExists | 409 |
  | 19 constraintViolation, 21 invalidAttributeSyntax, 65 objectClassViolation, 64 namingViolation, 34 invalidDNSyntax | 422 |
  | 50 insufficientAccessRights, 49 invalidCredentials | 403 |
  | 53 unwillingToPerform | 409 |
  | 4 sizeLimitExceeded, 3 timeLimitExceeded | 200 with `truncated: true` |
  | 13 confidentialityRequired (password generation over plain LDAP) | 422 |
  | 51 busy, 52 unavailable, 81 serverDown | 503 |
  | others | 500 |

- **DNs are passed in the query parameter** `?dn=...` (URL-encoded), not in the path — DNs contain `,`, `=`, `/` and spaces.
- Entry attributes are a list of `{ "name", "values": [...], "binary", "redacted", "operational" }`. `name` keeps attribute options (`cn;lang-ru`). When `binary` is true all values are base64; the decision is made per attribute from the schema syntax (`kind`), the `;binary` option, and — for Octet String — whether every value is printable UTF-8. Password attributes (`kind: password`) are never sent: `redacted` is true and each value is reduced to its `{SCHEME}`.
- Entry changes are sent as a set of operations, not a full replacement:
  ```json
  { "changes": [ {"op": "replace", "attr": "mail", "values": ["a@b.c"]},
                 {"op": "delete",  "attr": "description"} ] }
  ```
- Concurrent edits: entry reads return an `ETag` (hash of the user attributes, header and `etag` field); `PATCH /entries` accepts `If-Match` and answers `412 Precondition Failed` if the entry changed since. 389-ds has no assertion control, so the check is read-then-modify (a narrow race window remains).
- Server settings mutations return `restartRequired: bool`; the overall state is in `GET /system/state`.
- Pagination of large lists: a cursor (`cursor` = Paged Results cookie, base64), `pageSize`; the response contains `nextCursor`.
- Every request (except `/healthz`, `/readyz`) must arrive with a `Host` listed in `DSUI_ALLOWED_ORIGINS`, otherwise `421 Misdirected Request` — protection against DNS rebinding while there is no authentication. Mutations additionally require the `X-Requested-With: ds-ui` header and an allowed `Origin` (CSRF protection).

## Tasks (asynchronous operations)

- Operations that start a DS task respond with `202 Accepted` and `{ "taskId": "...", "dn": "cn=…,cn=tasks,cn=config" }`.
- `GET /tasks/{id}`: `{ status: "running|succeeded|failed", exitCode, progress: {current, total}, log: [..], startedAt, finishedAt }`.
- `taskId` is a stable ds-ui identifier (not a DN), so as not to depend on escaping.

## Events (SSE)

`GET /api/v1/events` — the shared stream:

| event | data |
|---|---|
| `task` | task status/progress change |
| `server` | `running` / `stopped` / `restarting`, `restartRequired` |
| `ping` | keep-alive every 15 s |

Log streams are separate SSE endpoints (`/logs/{name}/stream`), so as not to load the shared channel.
